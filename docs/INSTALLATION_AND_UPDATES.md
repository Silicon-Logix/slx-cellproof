# Installation, updates and recovery

## Windows installation

Download the installer or portable ZIP from the
[official releases](https://github.com/Silicon-Logix/slx-cellproof/releases).
The installer runs per user without administrative rights, creates shortcuts
and optionally associates `.cellproof` documents. Its default application folder
is `%LOCALAPPDATA%\Programs\Silicon LogiX\CellProof`.

Keep the portable executable, PCK, native core and notices together. Both forms
use the same local projects. Settings and recovery copies live under Godot's
user-data folder, normally `%APPDATA%\Godot\app_userdata\SLX CellProof`.
Uninstall removes installed application files and its registrations; it preserves
projects, preferences, recovery copies and previously downloaded installers.

## Preview integrity and publisher identity

The current release is an **unsigned development preview**. A SHA-256 checksum
detects a changed download; it does not authenticate a publisher. No production
certificate or production Ed25519 signing key is supplied or generated by this
project. The application, installer and release descriptions retain this status.

Verify a downloaded artifact against `SHA256SUMS.txt` from the same official release:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\slx-cellproof-0.5.0-windows-x64-setup.exe
Get-AuthenticodeSignature -LiteralPath .\slx-cellproof-0.5.0-windows-x64-setup.exe
```

The expected publisher status for this preview is `NotSigned`. A production
release requires a real publisher certificate, an externally controlled Ed25519
key, a matching embedded trusted public key and production update policy.
The packaging path refuses production mode without those prerequisites.

## Explicit update workflow

**Help / Check for updates** queries the fixed official GitHub repository only
after the operator chooses it. It sends no recipes, controller addresses or
project contents. The preview channel can see preview releases; production
policy excludes them. A candidate must have an official installer URL, a bounded
size and a published SHA-256 digest. No eligible candidate means no automatic
fallback to an unverified download.

The download is saved to a staging name under the local user-data folder and
checked before it becomes an installable candidate. **Install update** first
protects dirty projects through Save / Discard / Cancel. A separate launcher
checks the file again after CellProof exits, then starts the installer. Other
running instances prevent replacement. Projects and recovery data remain outside
the application installation directory.

With production policy, a trusted Ed25519 manifest must bind the exact installer
hash, version and certificate thumbprint. The Windows signature must be valid
and match that identity. Preview policy is displayed as unsigned and only
establishes transport/download integrity. The application never silently installs
an update or executes a failed verification.

## Recovery and rollback

Use **Project / Recover autosave** for unfinished work or **Restore previous save**
for the prior saved document. Project writes use native Windows atomic replacement,
retain a previous complete copy and reject a file changed by another writer.
An interrupted preparation leaves a checksummed `.pending-….cellproof` document
which can be opened as a local recovery copy. Reopened evidence is unverified.

Previously downloaded installers remain in the local updates directory. For a
deliberate application rollback, save a separate project copy, close all instances,
verify the previous installer and run it with `/ALLOWDOWNGRADE=1`. A normal
installer refuses to replace a newer application with an older one. This is an
explicit installer-based rollback; there is no background rollback service.

## Rebuild an installer from an approved runtime

Use Inno Setup **6.7.3** and Python 3.13. Start from an audited Windows runtime
folder and run:

```powershell
python scripts/build_installer.py .\approved-runtime --compiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

The recipe is in `installer/CellProof.iss`. The public source bundle contains
the interface and approved core binary; proprietary native core implementation
and issuer/private signing tools are excluded. Signing is a publisher operation,
not an end-user dependency. Complete Inno Setup terms are included in
`licenses/inno-setup-LICENSE.txt`.
